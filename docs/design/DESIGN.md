# DESIGN: Assets Studio 设计文档

> **状态**: ready-for-dev
> **对应原型**: `docs/design/prototype.html`
> **配套规范**: `docs/design/DESIGN-SPEC.md`
> **更新**: 2026-08-10

本文档描述 Assets Studio 桌面端的高保真原型设计（`docs/design/prototype.html`）背后的设计意图：为什么长这样、交互如何组织、哪些决策是刻意的。具体的可落地规范（token、组件、间距、动效）见 `DESIGN-SPEC.md`。

---

## 1. 设计目标

Assets Studio 是面向个人博客与微信公众号创作者的工具，核心价值是「本地图片 → 压缩 → 上传 → 复制 Markdown 链接」这条流水线走得足够快。

原型的三个设计目标：

1. **核心动作收敛**：整款工具只有 5 个动作（上传 / 浏览 / 复制链接 / 删除 / 查看详情），界面不得出现第 6 个无关入口。
2. **零管理负担**：存储按上传日期自动归档，月份自动切换，用户永远不需要手动迁移或重命名旧图。
3. **可信赖的反馈**：每一个动作都有即时、明确的状态反馈（进度、成功、失败、确认），让用户放心操作。

---

## 2. 设计读（Design Read）

**Reading this as:** 桌面端图片素材管理工具（Tauri，面向个人博客创作者），Linear 式克制动效语言，浅色 / 深色双主题，系统字体栈。

| 维度 | 值 | 理由 |
|---|---|---|
| DESIGN_VARIANCE | 4 | 工具类界面，图片栅格规整，版面服务效率而非艺术性 |
| MOTION_INTENSITY | 4 | 只保留有意义的动效：侧边栏折叠、悬停浮层、状态反馈，全部可被 `prefers-reduced-motion` 关闭 |
| VISUAL_DENSITY | 5 | 中等密度：栅格留白充足，但信息（文件名 / 大小 / 时间）完整可读 |

设计基调：**功能优先的克制**。不堆装饰、不加与核心动作无关的功能区、不动效炫耀。

## 3. 信息架构

侧边栏导航，共三个视图：

```
Assets Studio
├── 浏览图片        # 默认视图：图片栅格 + 悬停操作
├── 上传图片        # 大拖拽区 + 多文件上传队列
└── 设置            # 链接域名 / 存储路径模板 / 重命名规则
```

- 侧边栏可折叠为 68px 图标轨（`localStorage` 记忆状态），折叠后全部文字隐藏、仅保留图标。
- 顶部「上传图片」主 CTA 与导航项「上传图片」指向同一视图，语义一致，不重复触发上传动作本身。
- 底部的空间用量条为信息性展示（当前为 mock 数据），不属于核心动作。

## 4. 核心工作流

```
拖拽 / 选择图片
      │
      ▼
队列中逐张处理：压缩（oxipng）→ 上传
      │
      ▼
生成链接（域名 + 归档路径）
      │
      ▼
复制链接（卡片悬停 / 队列完成态 / 详情弹窗三处入口）
```

- 上传页支持一次多文件，队列逐张模拟「压缩 → 上传」两阶段进度。
- 上传完成后图片立即进入「浏览图片」列表顶部，计数实时更新。
- 复制链接三处入口文案统一为「复制链接」，成功反馈统一为绿色「已复制」+ 底部 toast。

## 5. 关键设计决策

### 5.1 核心动作收敛（对应 PRD「个人图床」定位）

原型删除了初版草稿中的「收藏」「设置占位」等菜单，只保留与 5 个核心动作直接相关的界面元素。判断标准：**这个按钮是否服务于上传、浏览、复制、删除、查看详情之一**。不属于的（如收藏）一律不进 v1 原型。

### 5.2 按上传日期自动归档，月份零管理

用户真实使用场景为 `blog/2026/08/20260810.webp` 结构。设计决策：

- 存储路径 = 模板 + 上传时刻的日期，由程序生成，**不依赖用户手动建目录或改链接**。
- 9 月上传自动进入 `blog/2026/09/`，旧图路径不变、链接永久有效（对象存储 key 稳定性）。
- 默认模板 `blog/{YYYY}/{MM}/{YYYYMMDD}.{ext}`，可在设置中改。

### 5.3 路径模板 + 正则重命名（设置页）

- 路径模板占位符：`{YYYY}` `{MM}` `{DD}` `{YYYYMMDD}` `{name}` `{ext}`。
- 重命名规则作用于文件名主体（扩展名保留），如 `我的 图片 01.webp` → `我的-图片-01.webp`（规则 `\s+` → `-`）。
- 设置页提供实时预览（重命名预览 + 「将存入」路径预览），所见即所得。

### 5.4 删除必须两阶段确认

删除是不可逆动作，卡片悬停与详情弹窗内的删除均采用「删除图片 → 确认删除？」两阶段交互，避免误触；卡片移出鼠标自动取消确认态。

### 5.5 上传队列取代单卡片进度

上传不是「一个按钮 → 一个结果」，而是可观察的过程：队列展示每张图的缩略图（真实文件预览，objectURL）、文件名、压缩前 → 压缩后体积、阶段进度与完成态。这让多文件上传可追踪、可等待、可逐个复制链接。

### 5.6 视觉系统摘要

完整 token 见 DESIGN-SPEC.md，此处记录意图：

- **单一强调色**：蓝（链接语义，贴合"复制链接"这一核心动作）；红色仅用于破坏性操作，绿色仅用于成功反馈。
- **系统字体栈**：桌面工具使用系统字体（含 PingFang SC / Microsoft YaHei），贴近原生应用质感，不引入网络字体。
- **圆角体系**：卡片 12px / 按钮 8px / 弹窗 16px / 胶囊 999px，一页只允许一套圆角规则。
- **无 emoji、无 em-dash**：图标统一为 1.7 描边宽的内联 SVG；文案只用中文标点。

## 6. 状态设计

每个界面元素都考虑完整状态循环，而不是只画"成功态"：

| 状态 | 实现 |
|---|---|
| 加载 | 首屏 8 个骨架屏卡片（shimmer，减少动效时静态灰块） |
| 空状态 | 删除全部图片后出现拖拽引导区，点击跳转上传页 |
| 上传中 | 队列进度条 + 阶段文案（压缩 → 上传）+ 百分比 |
| 上传完成 | 绿色完成态 + 压缩前后体积对比 + 复制链接按钮点亮 |
| 复制反馈 | 按钮变绿「已复制」约 1.6s + 底部 toast |
| 删除确认 | 两阶段：按钮变「确认删除？」红底白字 |
| 失败 | 复制失败 toast 提示手动复制；非法正则回退为原名 |

## 7. 暗色模式

- 双主题从第一版就存在，非浅色模式附带品。
- 全部颜色走 CSS 变量，`@media (prefers-color-scheme: dark)` 整体切换，遵循系统偏好。
- 暗色下强调蓝提亮（`#7aa7ff`）保持对比度；填充按钮保持深蓝 + 白字（对比度 6.4:1）。
- 禁止纯黑 `#000` 与纯白 `#fff`，均使用近黑 / 近白。

---

## 8. 可访问性与性能

- 对比度：正文文字 ≥ 4.5:1（WCAG AA），按钮文字以深蓝底白字保证 ≥ 4.5:1。
- 键盘：全站 `:focus-visible` 可见焦点环；弹窗支持 ESC 关闭、`role="dialog"`、`aria-modal`。
- 动效：所有动效仅 transform / opacity；`prefers-reduced-motion` 下全局关闭过渡与动画。
- 布局稳定：`100dvh` 视口高度，无 `h-screen` 跳动问题。
- 图标全部 `aria-hidden="true"`，图片有 `alt`，按钮有 `aria-label`。
